# Qiwi 2.2.2 → 2.3.0 线上升级手册

2.3.0 新增文章「段落想法」批注（读者框选正文就地留言、人工审核后可见），并对表情包选择面板做了一轮整理。本手册描述线上站从 2.2.2 升级到 2.3.0 的完整操作路径。

## 背景：这个版本动了什么

| 组件 | 变化 | 对升级的影响 |
| --- | --- | --- |
| `QiwiTheme` | 新增想法模块（`Thoughts.php`、`ThoughtsConsole.php`、`page/thoughts.php`）与 `qiwi-theme` action 下的 `do=thought-submit` 公开端点 | 需要停用再启用一次，激活时注册「Qiwi 想法审核」后台面板并顺手建表 |
| 数据库 | 新增独立表 `qiwi_thoughts`（想法数据），由 `CREATE TABLE IF NOT EXISTS` 按需创建 | **无需任何数据迁移**；既有表零改动，详见下节 |
| 主题配置 | 新增「想法批注」页签（功能开关、字数与选区限额、提交间隔、待审上限、待审邮件通知）；想法默认开启 | 已有配置不受影响，新键自动取默认值；不想开可在页签里关，或按文章在编辑页单独覆盖 |
| 表情包 | 微信表情包退出所有表情选择面板（评论区 / 时光机回复 / 想法），历史内容中的微信表情仍正常渲染 | 无操作；不想影响存量内容是刻意保留的 |
| `QiwiCap` / `Geetest` | 仅 `@version` 号更新，无功能与钩子变化 | **无需重新激活，无需任何操作** |

## 数据迁移：没有

这是本次升级最省心的一点，明确说一下边界：

- 新表 `qiwi_thoughts` 在 **QiwiTheme 重新激活时**创建；即使跳过激活，首次提交 / 读取想法时也会按需自动建表（同样的 `CREATE TABLE IF NOT EXISTS`）。
- 不修改任何既有表结构，不搬运任何配置；`theme:qiwi` 配置行只追加新键。
- 想法的「待审仅提交者自己可见」用独立签名 Cookie（`qiwi_own_thoughts`），与评论的 `qiwi_own_comments` 同一套签名体系，互不影响。
- 回滚到 2.2.2 时 `qiwi_thoughts` 表留在库里也无害——旧版本代码不读它，下次再升回 2.3.0 数据还在。

## 一、升级前备份（必做）

1. **全站目录**：含 `usr/themes`、`usr/plugins`、`config.inc.php`。
2. **数据库**：至少备 `options` 整表（重点是 `theme:qiwi` 与 `plugins` 行）。2.2.2 升级没有需要保数据的新表。

## 二、文件部署

### 路线 A：update.sh（推荐）

```bash
cd <线上主题目录>   # 例如 /opt/1panel/apps/typecho/.../usr/themes/qiwi
bash update.sh
```

自动完成：拉取最新代码 → 同步 `usr/plugins/` 下的 `Geetest`、`QiwiCap`、`QiwiTheme`。

### 路线 B：手动复制

**要复制 / 更新的：**

- `usr/themes/qiwi/` 整个主题目录
- `usr/plugins/QiwiTheme/` 整个目录——注意它新增了 `Thoughts.php`、`ThoughtsConsole.php`、`page/thoughts.php`，一个都不能少
- `usr/plugins/QiwiCap/`（仅版本号变化，建议一并更新保持版本一致；不更新也能正常跑）
- `usr/plugins/Geetest/`（仅当你在用 Geetest 时）

**没有需要删除的目录**（2.2.0 那次的 QiwiSitemap / QiwiCommentMail 清理早已完成）。

## 三、后台操作（核心步骤）

1. **「插件」页**：停用 `QiwiTheme`，再重新**启用**。
   - 这一步的目的：注册新的「Qiwi 想法审核」后台面板，并提前创建 `qiwi_thoughts` 表；
   - QiwiTheme 的配置都在主题配置行里，停用 / 启用不会丢设置；
   - 若激活提示想法数据表创建失败，排查数据库账号建表权限后重试；此状态下想法提交端点会提示「想法数据表尚未就绪」，其余功能不受影响。
2. **「外观 → 设置外观」**：检查新增的「想法批注」页签。
   - 想法功能默认开启；不想全站开启可在页签关闭，再按文章在编辑页单独打开；
   - 「待审邮件通知」默认开启，复用现有邮件队列，未配置 SMTP / Resend 时静默跳过。
3. `QiwiCap` / `Geetest` **不需要任何操作**。

## 四、升级后自检清单

- [ ] 打开任意一篇文章，鼠标框选正文两三个字，出现「写想法」气泡，点击展开浮窗；
- [ ] 游客身份（浏览器无痕窗口）首次提交需填称呼 + 邮箱；填过一次后再开浮窗，身份折叠为一行「以某某的身份发布」，点「修改」可展开；
- [ ] 提交后该段文字出现更浅的虚线标记（待审仅自己可见），列表里显示「待审核，通过后对所有人可见」；
- [ ] 后台「控制台」下拉里出现「Qiwi 想法审核」面板，待审想法可一键通过 / 删除；
- [ ] 通过后换浏览器 / 无痕窗口访问，虚线正常、想法对所有人可见；
- [ ] 评论区 / 时光机回复 / 想法浮窗的表情面板只剩可选表情包（本地微信包不再出现），历史内容里的微信表情仍正常显示；
- [ ] （可选）文章顶部阅读设置里可一键关闭「想法」，刷新后保持。

## 五、常见问题

- **升级后文章页没有「写想法」**：确认 QiwiTheme 已重新启用、主题设置「想法批注」里功能开着、该文章编辑页没有单独关闭；读者端也可能是自己在阅读设置里关过（跨访问保持），换无痕窗口验证。
- **提交一直「选区校验失败」**：文章正文刚被编辑过、字符轴偏移变了，重新框选一次即可（前端有锚点重定位，一般自动对上）。
- **管理员提交的想法去哪了**：管理员（administrator 登录）提交直接发布、免审核免验证码，作者标记为「作者」，头像优先用登录账号邮箱。
